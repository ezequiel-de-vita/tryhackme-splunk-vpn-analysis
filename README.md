# Splunk VPN Log Analysis (TryHackMe)

This repository contains notes, queries, and screenshots from a hands-on
Splunk Enterprise lab completed on TryHackMe. The focus of the lab was on
onboarding VPN logs into a SIEM and performing basic investigative
analysis similar to what a SOC analyst would do during daily operations.

The dataset represents VPN connection logs and was used to answer a set
of investigation-driven questions related to users, source IP addresses,
and geographic origin.

---

### What this lab covers

The work in this repository includes:

- Uploading structured VPN log data into Splunk
- Creating and validating a custom index for VPN events
- Ensuring correct parsing using the `_json` sourcetype
- Writing and refining SPL queries to answer specific investigation
  questions
- Applying filtering logic commonly used in SOC environments (user, IP,
  country, exclusions)

---

### Data ingestion details

The VPN log file was manually uploaded using Splunk’s **Add Data**
workflow to simulate a controlled onboarding scenario.

Configuration used during ingestion:
- Source type: JSON
- Sourcetype: `_json`
- Index name: `VPN_Logs`

This step was intentionally included to reflect real-world SIEM usage,
where analysts are often required to validate log ingestion before
analysis begins.

---

### Analysis approach

Once the data was indexed, multiple SPL searches were executed to explore
VPN activity from different angles. Rather than running generic searches,
each query was written to answer a concrete operational question.

Examples of analysis performed:
- Determining the total number of VPN events
- Identifying activity generated by a specific user account
- Mapping source IP addresses to usernames
- Filtering VPN connections by country, including exclusion logic
- Measuring the frequency of connections from specific IPs

Queries were adjusted iteratively to ensure accurate results and to
follow efficient search practices.

---

### Investigation questions addressed

During the lab, the following questions were answered using SPL:

- How many VPN events exist in the dataset?
- How many events are associated with a given user?
- Which user is linked to a specific source IP address?
- How many VPN connections originated from all countries except a trusted
  one?
- How many VPN events are tied to a specific IP address?

These questions are representative of common SOC tasks such as basic
triage, anomaly identification, and contextual investigation.

---

### Why this matters from a SOC perspective

This lab focuses on fundamental SIEM skills expected from junior and
entry-level SOC analysts:

- Verifying that logs are correctly ingested and searchable
- Writing clear and efficient SPL queries
- Correlating users, IPs, and geographic data
- Thinking in terms of investigation questions rather than raw log
  volume

Being able to move from raw logs to meaningful conclusions is a core part
of security operations work.
